## Method and limits

- **Head SHAs:** every PR head was fetched from `refs/pull/<n>/head` and matched to the API head SHA (127/127 matched).
- **Behind and conflict:** "behind" is commits on base since the merge-base. "Conflict" is `git merge-tree --write-tree base head`; it is not GitHub's `mergeable` field.
- **"On base":** the share of each PR's added lines (≥20 characters; `HANDOFF_LOG.md` and `CURRENT_STATE.md` excluded) that already appear verbatim in the same file on base. A high share on a test follow-up means the parent merged and only the new test is left. Superseded calls rest on a named base commit found by `git log` and `git grep`, not on the share.
- **Required CI:** the latest check run per required context (`config/required-status-checks.json`, 35 contexts) at the PR's current head, read with `gh api` on 2026-10-27. **A green result at a head 100+ commits behind base is not current.** "Not reported" means `ci.yml` never ran at that head. That is common for cursor[bot] drafts.
- **Protected tags** come from path rules (workflows, governance files, migrations, edge function sources, lockfiles, `package.json`, Paddle/checkout/payments source). Test and e2e files are not tagged.
- **Delegated checks:** semantic "superseded?" checks were split across read-only subagents and then cross-checked against git evidence. Lines marked "inference" were not proven.
- **Scorer lock:** `node scripts/scorer-lock.mjs --report --strict` was not run. This PR adds one docs file and touches no tests.
