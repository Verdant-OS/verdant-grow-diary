## 1. Evidence classes

Each measurement cell carries exactly one class:

| Class                                  | Meaning                                                                                                                                                              |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CANON`                                | Current canonical behavior, derived by direct source reading at the pinned tip, with file:line anchors                                                               |
| `CANON+TEST`                           | `CANON` plus a local unit/static suite receipt from §2 exercising the behavior                                                                                       |
| `PENDING-PR`                           | Behavior of an open, unmerged PR (none apply at this pin — #1029 and #1034 both merged before measurement)                                                           |
| `MOCKED-E2E`                           | Mocked-browser (Playwright `chromium-mocked`) runtime evidence, captured by the PR-B0a interaction counter and recorded here as the authoritative exact before-value |
| `AUTH-LIVE`                            | Authenticated live/production evidence — `BLOCKED` this session (see §5)                                                                                             |
| `NOT_MEASURED` / `BLOCKED` / `MISSING` | Per the repository status vocabulary; `MISSING` marks an affordance that does not exist in the product                                                               |

**Counting rules** (fixed for all before/after comparisons):

- **Interaction** — one deliberate tap/click/Enter on a control that advances
  the flow. Scrolling, focus moves, and passive reading do not count. Opening a
  `Select` and choosing an option counts as 2.
- **Typing** — number of free-text fields the flow _requires_ (not optional
  fields). 0 means the flow completes with no keyboard text entry.
- **Target reselection** — any grow/tent/plant selection the grower must make
  when the app already had that context available (route, prior selection, or
  prefill).
- **Route transition** — full route navigations during the scenario.
- **Duplicate-write risk** — LOW / MEDIUM / HIGH from the surface's idempotency
  mechanics (§4), not from observed duplicates.
- Elapsed time is **not** measured in this container (no headed run; CI
  wall-clock is banned as a UX metric). Manual headed timings are a Phase B
  verification step.

## 4. Cross-surface facts the counts rest on

All `established fact` from direct source reading at the pin, cross-checked
against `docs/specs/one-tent-loop-quicklog-single-write-path.md` and the
Tranche A specification.

**Canonical save contract.** `quicklog_save_manual` via
`useQuickLogV2Save.ts:44-47` (payload `quickLogV2SavePayload.ts`; since #1034
transport errors are classified by `classifyQuickLogThrownSaveError`). The
repo skill's "ONLY persistence path" invariant is not what ships; live
divergences, by surface:

1. `quicklog_save_event` RPC — three live call sites
   (`useQuickLogActivitySave.ts:192`, `writeQuickLogWateringTypedEvent.ts:265`,
   `writeFeedingTypedEvent.ts:245`).
2. Direct `diary_entries` INSERT for photo (`quickLogPhotoDiaryEntry.ts:104`)
   and video (`quickLogVideoDiaryEntry.ts:86`) — deliberate ("the event RPC
   would confirm an invisible photo").
3. Duplicated inline `quicklog_save_manual` payload in
   `useQuickLogActivitySave.ts:132-148` — omits `p_stage`; passes
   `p_idempotency_key: null` when the key fails its length check, silently
   disabling server dedupe; collapses reason codes (deferred in #1034 to
   protect Tranche A5 anchors).
4. Direct `diary_entries` UPDATE photo patch (`PlantQuickLog.tsx:325-328`).
5. Direct `grows` UPDATE stage side-write (`QuickLog.tsx:1205`).
6. Dead-but-compiled `createQuickLogEvent` (`quick-log/createQuickLogEvent.ts:95`).

**Idempotency ranking** (drives the Dup column): legacy `QuickLog` strongest
(signature-aware key reuse, `QuickLog.tsx:1162-1170`) > `QuickLogV2Sheet`
(rotate-on-success + frozen watering retry lock) > `PlantQuickLog`
(`saveKey ?? newQuickLogSaveKey()` fallback at :298 can re-mint per attempt;
only a `busy` flag guards re-entry) > `QuickLogAllActivitiesSection` (fresh
key per click, `:535`; no refresh, no toast — the silent-success re-tap is the
repo's highest duplicate-write exposure).

**Status-first parity.** Better/Same/Worse exists only in `PlantQuickLog`
(:477-484) and legacy `QuickLog` (:2025-2032), as note text. `QuickLogV2Sheet`
and `QuickLogAllActivitiesSection` have no status chips.

**`verdant:entry-created`** is dispatched in five shapes; the AppShell-mounted
legacy dialog double-fires per save (`QuickLog.tsx:1256` + `AppShell.tsx:358`)
until A5(d) lands (approved, incoming).
